## 1. 결론: 전면 개편은 **권하지 않습니다**

unslop은 "AI가 찍어낸 티가 나는 화면"을 사람이 디자인한 화면으로 바꾸는 작업입니다.
학원노트는 그 대상이 아닙니다. 감사 목록 7개 묶음(색·타입·아이콘·간격·카피·부품·모션) 약 50개 항목 중 **실제로 걸린 것은 4개**뿐입니다.

걸리지 **않은** 것들 (AI 티가 나는 화면이면 거의 다 걸리는 항목):

| 흔한 증상 | 학원노트 |
|---|---|
| 보라–분홍 그라데이션, 글자 그라데이션 | 없음 (로고 하나 빼고) |
| 색 번짐(글로우), 색 그림자, 떠다니는 얼룩 | 없음 (로고 하나 빼고) |
| 이모지를 아이콘·꼬리표로 씀 | **0개**. 아이콘은 직접 그린 선 아이콘 한 세트, 굵기 1.8 하나 |
| `New ✨`, `PRO` 같은 가짜 배지 | 없음 |
| 과장 문구("한 번에 해결!", 느낌표) | 없음. 전부 평서문 |
| `mt-[13px]` 같은 제멋대로 간격 | 없음. 전부 0.25rem 단위 |
| 이유 없이 깜빡이거나 튀는 움직임 | 없음. 전환은 4곳뿐 |
| 전부 알약 모양 | 아님. 단추 10px, 카드 16px, 배지만 알약 |

그리고 지금 모습의 상당 부분은 **사용자가 직접 요청해서 정해진 것**입니다 — 남색 테마와 로고(decisions 35), 메뉴 위치(36), 달력 격자와 칩(37·41), 항상 밝은 화면(39), 글자 17px로 키움(42), 시간표 7시~24시 전부 보이기(43), 폰 시간표 글자 축소(64).
unslop 교과서대로라면 "제목 굵기 800 → 400~500으로", "색 가짓수 줄이기", "부제 마침표 빼기" 같은 걸 손대야 하는데, 이건 전부 **이미 정한 결정을 되돌리는 일**입니다. 그러면서 눈에 띄게 예뻐지지도 않습니다. 딱 "애매하게 바꾸는" 경우라 넣지 않았습니다.

**그래서 제안은 전면 개편이 아니라, 아래 5개짜리 손질 목록입니다.** 5개 다 해도 CSS 중심 소규모 수정이고, 화면의 성격은 그대로입니다.

## 2. 지금 화면의 성격 (손질할 때 지킬 기준)

unslop은 고치기 전에 "이 제품은 무엇인가"를 다섯 줄로 못박게 합니다. 새로 만든 게 아니라 **지금 앱에서 읽어낸** 다섯 줄입니다. 아래 손질은 전부 이 선 안에서만 합니다.

- **제품**: 아이 둘의 학원비·출석·보강·주간 학습을 부모가 폰에서 챙기는 기록장
- **성격**: 조용하다, 정확하다, 손이 빠르다 (장식보다 숫자와 날짜가 먼저 읽혀야 함)
- **세계**: 종이 노트와 달력. 흰 종이, 가는 괘선, 색 인덱스 스티커 — 지금의 흰 카드·회청색 바탕·격자가 이미 여기에 맞음
- **눈에 띄는 자리**: ① 달력/시간표 격자 ② 학습 보드의 체크 칸. 색과 밀도는 여기에만 두고 나머지는 조용하게
- **이 앱만의 표시**: **자녀 색 점**. 위쪽 선택, 목록 행, 달력 칩 왼쪽 띠, 시간표 블록까지 같은 색이 따라다님 — 이미 일관됨

## 4. 찾았지만 **일부러 넣지 않은 것**

왜 뺐는지까지 적습니다. 나중에 "이건 왜 안 했지" 하지 않으려고요.

| 항목 | unslop 교과서 | 왜 안 하는가 |
|---|---|---|
| 제목 굵기 800 (`.page-title`, `.topbar-brand`, `.cal-chip-tag`, 로고) | 400~500으로 낮추고 크기로 위계를 줘라 | 글자를 **키워 달라**는 요청(decisions 42)으로 잡은 굵기입니다. 낮추면 "흐려졌다"로 느껴지기 쉽고, 바꿔도 티는 거의 안 납니다. 전형적인 "애매한 변경" |
| 화면 부제의 마침표 ("오늘 할 일을 한눈에 확인하세요.") | 짧은 글에는 마침표 금지 | 영어 라벨 기준 규칙입니다. 한국어 존댓말 안내문에서 마침표를 빼면 어색합니다 |
| 색 가짓수 (자녀·학원 8색 + 상태 4색) | 중립 색 하나 + 강조 하나 | 색마다 뜻이 있습니다(어느 아이·어느 학원·결석/휴강/보강, decisions 41). 줄이면 기능이 줄어듭니다 |
| 달력 칩의 잘린 이름 ("한빛⋯") | 말줄임표(…)로 | 좁은 칸에서 **이름 앞부분을 최대한** 보여주려고 일부러 자른 것(decisions 33). 말줄임표를 넣으면 글자가 한 칸 더 줄어듭니다 |
| PC(1366)에서 본문이 680px로 묶여 오른쪽이 빔 (`.narrow`) | 화면을 꽉 채워라 | 사실이지만, 이건 **폰 앱**입니다. PC는 인쇄와 개발용이고, 넓히면 달력·시간표·납부 화면 배치를 전부 다시 짜야 합니다. 비용 대비 이득이 가장 나쁨 |
| 폰 시간표 블록 글자가 세로로 한 자씩 | 가로로 읽히게 | 좁은 화면에서 가로 스크롤을 없애려고 정한 방식(decisions 51·64). 되돌리면 가로 스크롤이 돌아옵니다 |
| 히어로 그림, 장식 그래픽 추가 | 랜딩 화면에는 큰 시각물 | 랜딩 화면이 없는 도구 앱입니다. 넣을 자리가 없고, 넣으면 그게 바로 AI 티입니다 |

## 5. 하는 순서와 확인

1~5번은 서로 안 엮여 있어서 따로따로 해도 됩니다. 추천 순서는 **1 → 3 → 2 → 4 → 5**(눈에 띄는 순).

- 1·3번은 `npm run test:e2e`로 폰 세로·가로·PC에서 가로 넘침이 없는지 확인 (`expectNoHorizontalOverflow`가 이미 있음)
- 2·4·5번은 CSS만 바뀌므로 화면만 눈으로 확인
- 6번은 시간표 e2e(`tests/e2e/timetable.spec.ts`)가 블록을 찾는 방식에 영향이 있는지만 확인
- 전부 `npm test`(계산 테스트)와는 무관

예상 작업량: 1~5번 합쳐서 `index.css` 약 20줄 + `PaymentsPage.tsx` 소폭. 6번은 `TimetablePage.tsx`에 `useEffect` 하나.
