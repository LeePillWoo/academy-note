# 보안 점검 (1차 마무리, 2026-10-31)

학원노트 v1.0.0(웹 + 디버그 APK)을 대상으로 코드와 설정을 훑어본 결과입니다. 자동 도구(`npm audit`)와 직접 검토를 함께 했습니다.

## 한눈에 보기

| 영역 | 결과 | 남은 일 |
|---|---|---|
| 입력 검증 | 양호 | - |
| HTML 삽입(XSS) | 양호 | - |
| 네트워크 | 양호 (혼자 쓰기는 요청 없음) | - |
| 가족 공유(Firebase) | 규칙 파일 준비됨 | 콘솔에 규칙 적용, App Check 검토 |
| 안드로이드 설정 | 양호 | 배포 전 release 서명 |

| 의존성 | 실제 영향 없음 (아래 설명) | 버전 추적 |

## 항목별

### 1. 들어오는 값 검사
- **백업 파일 가져오기**(`src/data/backup.ts` `parseBackup`): 밖에서 오는 파일이라 믿지 않습니다. `app`이 `academy-note`인지, `version`이 지원 범위인지, `data`가 객체인지 확인하고, 아는 데이터 종류만 받으며, `id`가 글자가 아닌 기록은 버립니다. 날짜가 없으면 빈 글자로 채웁니다. 가져오기 전에 내용 요약을 보여주고 확인을 받습니다.
- **가족 코드**: 12자, 정해진 32글자만 허용(정규식). 틀리면 서버에 묻지 않고 안내합니다.
- **Firebase 설정 붙여넣기**: JSON으로 바꿔 `apiKey`, `projectId`, `appId`가 글자인지 확인한 것만 저장합니다.
- **금액**: 숫자만 남겨 변환(`parseAmount`). **날짜**: 형식과 실제 존재 여부 검사(`isValidDate`). **주소의 `?date=`**: 검사 후 틀리면 오늘로 대체.
- **알림 탭 링크**: `/`로 시작하는 앱 안 경로만 따라갑니다(`onNotificationTap`).

### 2. HTML 삽입(XSS)
- React가 모든 글자를 이스케이프합니다. `dangerouslySetInnerHTML`, `innerHTML`, `eval`은 쓰지 않습니다(코드 검색으로 확인).
- 학원 이름 같은 사용자 입력이 알림 제목에 들어가지만 글자로만 쓰입니다.

### 3. 외부 링크와 프로토콜
- 학원 연락처의 전화 링크는 숫자와 `+`만 남긴 뒤 `tel:`을 붙입니다. 다른 프로토콜이 끼어들 수 없습니다.
- 앱이 여는 외부 주소는 없습니다.

### 4. 네트워크
- **혼자 쓰기(기본)**: 네트워크 요청이 전혀 없습니다. Firebase 코드는 별도 조각(chunk)으로 나뉘어 가족 코드를 만들거나 참여할 때만 내려받습니다. 화면 테스트(`tests/e2e/family.spec.ts`)에서 구글·Firebase로 나가는 요청이 0건임을 확인합니다.
- 개발 서버(`npm run dev:phone`)는 같은 와이파이에 열리지만 개발 중에만 켭니다. APK 내려받기용 임시 서버도 작업 뒤 꺼집니다.
- APK의 웹뷰는 `https` 스킴을 쓰고 평문 통신(cleartext)은 기본값대로 막혀 있습니다.

### 5. 가족 공유(Firebase)
- 로그인은 **익명**이며 접근은 **가족 코드를 아는지**로 나뉩니다. 코드는 32^12(약 1.2×10^18) 가지라 추측이 불가능하지만, **코드가 곧 열쇠**이므로 가족에게만 알려야 합니다. 앱 화면에도 이 점을 적어 두었습니다.
- `firestore.rules`: 로그인한 앱만, 그리고 12자 코드 형식의 경로만 읽고 쓸 수 있습니다. 전체 목록 조회는 막힙니다. **테스트 모드로 만든 데이터베이스는 30일 뒤 모두 막히므로 반드시 이 규칙을 콘솔에 적용해야 합니다.**
- `apiKey` 등 설정값은 비밀이 아닙니다(앱에 넣어도 됨). 보호는 규칙이 맡습니다.
- 개선 과제: Firebase **App Check**(우리 앱에서 온 요청만 허용), 코드 **재발급**(유출 시 새 코드로 옮기기), 선택적 **구글 로그인**(기기 바꿔도 복구, 누가 기록했는지 표시).

### 6. 안드로이드
- 지금 APK는 **디버그 서명**이라 `android:debuggable`이 켜져 있습니다. USB 디버깅이 켜진 PC에 연결하면 앱 데이터를 읽을 수 있으므로 **배포용은 4단계에서 release 키로 서명**합니다. 서명 키는 Git에 올리지 않습니다(`.gitignore`에 `*.jks`, `*.keystore`).
- 권한: 인터넷, 알림(`POST_NOTIFICATIONS`, 안드로이드 13+에서 사용자 허용 필요), 정확한 알람(플러그인이 선언, 허용 안 되면 일반 알람으로 동작). 저장소 권한은 없습니다. 백업 파일은 앱 임시 폴더에 쓴 뒤 공유 창으로 넘깁니다(FileProvider).
- `allowBackup`은 기본값(허용)입니다. 구글 기기 백업에 앱 데이터가 포함될 수 있으나 사용자 계정 안에서만 복원됩니다.

### 7. 저장된 데이터
- 기록(자녀 이름, 학원, 연락처, 납부)은 폰의 앱 전용 영역에 **평문**으로 저장됩니다. 다른 앱은 읽을 수 없고(루팅 제외) 보호는 기기 잠금에 의존합니다.
- 백업 파일도 평문 JSON입니다. 카카오톡·드라이브로 보낼 때는 그 서비스의 보안에 맡겨집니다.
- 개선 과제: **앱 잠금(PIN·지문)**, **백업 파일 암호화(비밀번호)**. 요청이 있으면 넣습니다.

### 8. 의존성
- `npm audit`: `@grpc/grpc-js` high 4건. Firestore가 **서버(Node.js) 환경에서만** 쓰는 통신 라이브러리입니다. 브라우저·APK 번들에는 들어가지 않음을 확인했습니다(빌드 결과에서 `grpc-js`, `@grpc`, `ChannelCredentials` 식별자 0건, `grpcFlowControlWindow`라는 설정 이름만 있음). 따라서 앱에는 영향이 없지만 Firebase 업데이트 때 함께 올라가는지 지켜봅니다.
- npm이 차단한 설치 스크립트 2개(`@firebase/util`, `protobufjs`의 postinstall)는 허용하지 않은 채로 빌드와 테스트가 모두 정상입니다.

### 9. 테스트
- 계산 테스트 73개, 화면 테스트 11가지 시나리오 × 3화면(폰 세로·가로, PC). 백업 가져오기의 잘못된 파일 처리, 가족 코드 형식 검사, 혼자 쓰기에서 네트워크 요청 0건도 테스트에 포함되어 있습니다.

## 개선 과제 (우선순위 순)
1. 배포 전 release 서명 키로 APK 만들기 (4단계)
2. Firestore 규칙을 콘솔에 적용하고 가족 공유 실제 연결 테스트
3. 앱 잠금(PIN·지문)
4. 백업 파일 비밀번호 암호화
5. Firebase App Check, 가족 코드 재발급
